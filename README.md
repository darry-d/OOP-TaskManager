# Менеджер завдань (Task Manager) - Лабораторна робота №7

## Тема
Робота з файлами. Потоки введення-виведення. Серіалізація.

## Опис проєкту
У цій лабораторній роботі застосунок «Менеджер завдань» доповнено повноцінною роботою з файловою системою: додано збереження й завантаження даних у текстовому та бінарному форматах, створення резервних копій у ZIP-архівах, систему логування дій користувача з автоматичною ротацією файлів, керування директоріями через NIO.2 та перевірку PIN-коду при вході. Усі потоки введення-виведення закриваються автоматично через `try-with-resources`.

## Що було реалізовано в межах ЛР №7:

1. **Текстове збереження та завантаження (`BufferedReader` / `BufferedWriter`):**
   Створено клас `TextStorage`, який зберігає у файл `tasks_db.txt` та відновлює з нього дані двох сутностей застосунку — `Project` і `Task` (`RegularTask` та `UrgentTask`) зі збереженням оригінальних `id` і статусів. Формати запису та читання повністю узгоджені.
2. **Бінарна серіалізація (`ObjectOutputStream` / `ObjectInputStream`):**
   Оновлено клас `Storage` із використанням `try-with-resources`, а також реалізовано інтерфейс `Serializable` для узагальненого сховища `Repository<T>`. Проєкт і всі його завдання серіалізуються у файл `my_tasks.dat` та коректно завантажуються після перезапуску.
3. **Робота з файловою системою (NIO.2 — `Path` та `Files`):**
   У класах `ActionLogger`, `BackupManager` та `TextStorage` реалізовано перевірку існування файлів і папок (`Files.exists`), автоматичне створення директорій `logs/` і `backups/` (`Files.createDirectories`), визначення розміру файлів у байтах (`Files.size`) та видалення застарілих логів і бекапів (`Files.deleteIfExists`).
4. **Резервне копіювання у ZIP та відновлення (`BackupManager`):**
   Реалізовано архівування файлів даних (`my_tasks.dat`, `tasks_db.txt`) у ZIP-архів із міткою часу (`ZipOutputStream`) в папку `backups/` та відновлення даних із найновішого архіву (`ZipInputStream`) з перезавантаженням поточного проєкту.
5. **Логування дій із ротацією файлів (`ActionLogger`):**
   Ключові дії користувача (запуск, перегляд, додавання, видалення, збереження, бекап) записуються з часовою міткою у текстові файли в папці `logs/` через буферизований потік `BufferedWriter`. Після досягнення ліміту в 5 рядків автоматично створюється новий файл лога (`app_log_1.txt`, `app_log_2.txt` тощо).
6. **Додатково — введення чутливих даних (`Console`):**
   На старті програми реалізовано вхід за PIN-кодом (`1234`) через `System.console().readPassword()` для прихованого вводу в системній консолі (з автоматичним переходом на `Scanner` при запуску з вбудованої консолі IDE).

## Функціонал меню (Інструкція з використання)
Після запуску `Main.java` та введення PIN-коду, окрім команд попередніх ЛР (`[1]`–`[12]`), доступні нові пункти ЛР №7:
- `[13]` Очистити застарілі логи (NIO.2 — перегляд розміру та видалення старих файлів)
- `[14]` Створити ZIP-бекап даних (бінарне збереження та архівація у `backups/`)
- `[15]` Відновити дані з останнього ZIP-бекапу
- `[16]` Зберегти дані у TXT-базу (`BufferedWriter`, файл `tasks_db.txt`)
- `[17]` Завантажити дані з TXT-бази (`BufferedReader`, файл `tasks_db.txt`)

# Менеджер завдань (Task Manager) - Лабораторна робота №9

## Тема
Породжувальні шаблони проєктування ООП (сімейство GoF).

## Опис проєкту
У дев'ятій лабораторній роботі застосунок «Менеджер завдань» доповнено трьома породжувальними шаблонами проєктування GoF, написаними власноруч без сторонніх бібліотек і вбудованими в основну логіку програми. Основний варіант за номером у журналі (№6, `6 mod 5 = 1`) — Фабричний метод; додатково реалізовано потокостійкого Одинака та Прототип.

## Що було реалізовано в межах ЛР №9:

1. **Фабричний метод (Factory Method — основний варіант):**
   Створено абстрактну фабрику `TaskFactory` та дві конкретні реалізації для кінцевих класів ієрархії завдань — `RegularTaskFactory` (створює `RegularTask`) і `UrgentTaskFactory` (створює `UrgentTask`).
    - **Інтеграція:** пряме створення об'єктів через `new` у пунктах додавання завдання (`[2]` та CSV-імпорт `[10]`) замінено викликом `factory.createAndAdd(...)`, що централізує створення, додавання в проєкт і логування.

2. **Потокостійкий Одинак (Thread-safe Singleton):**
   Клас `ActionLogger` переведено на шаблон Singleton із приватним конструктором, полем `volatile` та подвійною перевіркою блокування (`synchronized`) у методі `ActionLogger.getInstance()`.
    - **Інтеграція:** увесь застосунок (включно з `Main` і `TaskFactory`) звертається до одного єдиного екземпляра логера, що унеможливлює конфлікти запису в спільні файли логів.

3. **Прототип (Prototype):**
   Реалізовано власний механізм клонування `cloneTask()` для власної ієрархії класів `Task` (`RegularTask` та `UrgentTask`) без використання стандартного `Cloneable`.
    - **Інтеграція:** конструктор глибокого копіювання `Project` тепер реально клонує кожне завдання через `cloneTask()`, а в меню додано функцію дублювання існуючого завдання зі створенням нового `id`.

## Нові пункти меню (ЛР №9)
Окрім оновленої логіки створення завдань у `[2]` та `[10]`, додано:
- `[23]` Продублювати завдання (демонстрація патерну Прототип)
- `[24]` Перевірити потокостійкого Одинака (запуск двох паралельних потоків і перевірка ідентичності посилань `ActionLogger.getInstance()`)
